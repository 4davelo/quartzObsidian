# Hiérarchie des Documents Contractuels

## Synthèse

La hiérarchie des documents contractuels est le raisonnement qui permet de décider quelle pièce du marché prime lorsqu'un plan, un texte, un métré, une annexe, une référence technique ou une clause générale semblent se contredire.

Elle prolonge le concept de [[concepts/documents-du-marche|Documents du Marché]] : cette page ne liste pas toutes les pièces, elle explique comment les ordonner pour sécuriser une offre, une demande de clarification, une exécution ou une réception.

## Exigences contractuelles / réglementaires

Le dossier doit d'abord être lu selon les règles propres au marché concerné. Le [[concepts/csc|CSC]], le tome A du [[entities/cctb|CCTB]], les clauses administratives, les règles générales d'exécution et les annexes peuvent fixer un ordre de priorité explicite.

Dans le corpus CCTB, une règle centrale ressort pour les contradictions de base entre pièces techniques :

1. les plans ;
2. le [[concepts/csc|CSC]] ;
3. les métrés.

Cette règle ne dispense pas de lire les autres clauses : les avis, modèles de documents, annexes, plans de détail, documents permanents du maître d'ouvrage, prescriptions produit, notes de calcul et documents de réception peuvent tous déplacer une obligation si le marché les rend applicables.

## Implications de livraison

Pour une entreprise, la hiérarchie documentaire sert à :

- détecter les contradictions avant dépôt de l'offre ;
- poser des questions écrites plutôt que chiffrer une hypothèse fragile ;
- éviter de fonder un prix uniquement sur un métré si les plans ou le texte imposent autre chose ;
- justifier une réserve ou une demande de précision ;
- préparer les études d'exécution, notes de calcul, fiches techniques et documents de réception attendus.

Lorsqu'un dossier active le [[entities/cct-105|CCT 105]], la hiérarchie doit intégrer ses articles techniques et administratifs applicables. Les exigences de calcul, choix de matériel, documents à introduire et essais peuvent créer des obligations qui ne sont pas visibles dans le seul CCTB.

## Bonnes pratiques techniques

La lecture pratique consiste à reconstruire un paquet documentaire unique :

- avis ou invitation ;
- [[concepts/csc|CSC]] ;
- plans ;
- métrés ou inventaires ;
- clauses administratives et techniques types ;
- annexes du pouvoir adjudicateur ;
- référentiels techniques explicitement cités ;
- addenda, questions-réponses et documents corrigés ;
- livrables de chantier et de réception.

Chaque contradiction doit être qualifiée : erreur de quantité, divergence plan/texte, référence manquante, limite de prestation ambiguë, interface non attribuée, ou exigence qui n'apparaît que dans une annexe. Ce classement guide la question à poser et le risque à provisionner.
